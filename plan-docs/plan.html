決定は基本的に私（エージェント）が埋めています。要確認 が付いたものは自信が80%以下だった箇所なので、そこだけ重点的に見てください。判断が変わったら、その場で言ってもらえれば差し替えます。

1プロダクト

一文で

書く前に需要が分かる、タイムライン型の実績ログ。

背景と課題

  • すべての成果を長いブログ記事に仕上げるコストが、AI時代に見合わなくなっている。
  • 一方で、日々やったことや技術的な成果は公開可能な形で残しておきたい。
  • PC・スマホ・AIエージェントのどこからでも、短時間で記録したい。

ゴール

  • タイトルと一言だけで実績を公開でき、1件を1分以内で登録できる。
  • 時系列で誰でも眺められ、タグで絞り込める。
  • 需要や気分が乗った実績に、後から Markdown の詳細を足せる。
  • MCP から追加・編集・削除・取得ができる。
  • X に貼ったときに、実績カードとして映える OGP が出る。

MVP でやらないこと

  • プッシュ（匿名リアクション）。トラフィックが無いうちは信号として成立せず、実装が一番重いため v1.1 に回す。データモデルに Reaction は作らない。
  • やる宣言（未達成フラグ）。
  • 下書き・非公開状態。作成は即公開のみ。
  • 階級（GOLD / SILVER / BRONZE）やレア度。完了や分布の概念が無く、出すと嘘になる。
  • 投稿用 Web 管理画面。投稿は MCP 経由のみ。
  • 閲覧者アカウント、フォロー、コメント。
  • 通知、リッチテキスト編集、全文検索、画像アップロード。

2決定事項サマリ

論点決定理由
投稿経路MCP のみ投稿者は1人。認証・フォーム・CSRF の工数を削れる
プッシュ作らない信号が成立しない。実装が最も重い
階級・レア度作らない算出根拠が無い
下書き作らない即公開のみ。状態遷移を持たない
永続化D1 + Drizzle単一文の UPSERT で整合が取れる。マイグレーションが運用に乗る
ホスティングCloudflare Workers既に保有。D1 と同居できる
MCP の置き場所本体 Worker の /mcpデプロイ1つ。管理ロジックを二重定義しない
MCP の認証Cloudflare Access（サービス トークン）Zero Trust で閉じる。実装は Worker 側で Cf-Access-Jwt-Assertion を検証
スマホからの投稿MVP 外OAuth が要る。MCP が安定してから
タイムラインの並び実施日の降順「いつやったか」が主。公開日はメタとして保持のみ
タグの複数指定AND絞り込みの意図に合う
削除ソフトデリート。URL は 410 Gone共有済みリンクに誠実。復元可能
Markdown読み取り時に変換 + サニタイズ保存時に HTML を持つとサニタイズ漏れが残る
OGP 画像共通の固定 PNG を Static Assets から配信取得時に画像を生成せず、実績データは D1 を正本にする
OGP のエンブレム使わない階級が無いので不要。タイポと縦線で見せる
OGP のフォント文字を PNG に焼き込み、実行時フォントなしWorker に画像レンダラやフォントをバンドルしない
アクセス解析入れないプライバシー。Cloudflare のログで足りる
ライセンスprivate のまま個人サイト

5データモデル

D1 は SQLite。真偽値・日時の専用型が無いので、INTEGER（0/1）と TEXT で持つ。

Achievement

列型制約説明
idTEXTPK不変のID（ULID か UUIDv7）
slugTEXTUNIQUE, NOT NULLURL 用。作成時に確定し変更しない
titleTEXTNOT NULLタイトル
summaryTEXTNOT NULL一言説明
body_markdownTEXTNULL 可詳細本文。無ければ「詳細はまだありません」
cover_image_urlTEXTNULL 可外部URLのみ
occurred_atTEXTNOT NULLYYYY-MM-DD（Asia/Tokyo）要確認
published_atTEXTNOT NULL公開日時（ISO8601）
created_at / updated_atTEXTNOT NULLISO8601
deleted_atTEXTNULL 可ソフトデリート日時
revisionINTEGERNOT NULL, DEFAULT 1楽観ロック。更新のたびに +1

インデックス

CREATE INDEX idx_achievement_alive   ON achievement(deleted_at, occurred_at DESC);
CREATE UNIQUE INDEX idx_achievement_slug ON achievement(slug);

Tag / AchievementTag

テーブル列
tagid, name（表示名）, normalized（UNIQUE）, created_at
achievement_tagachievement_id, tag_id（複合PK）

正規化は NFKC → 小文字化 → 前後空白除去 → 連続空白の圧縮。表示名は別に持つので、Cloudflare と cloudflare は同じタグに寄る。

Link

列型説明
id / achievement_idTEXT実績に従属
urlTEXThttp / https のみ許可
labelTEXT表示ラベル（任意）
positionINTEGER表示順

AchievementRevision

復元用のスナップショット。更新のたびに変更前の状態を1行積む。 

achievement_revision(
  id, achievement_id, revision,
  snapshot_json,          -- 変更前の Achievement 全体
  source,                 -- 'mcp' | 'system' | 'restore'
  created_at
)
監査ログについて要確認

原本の要件では「監査ログ」と「変更履歴」を別々に持つ想定でしたが、個人1人の運用では重複します。MVP では 変更履歴の source カラムで代替し、独立した監査ログテーブルは作りません。Workers のログにも操作は残ります。

作らないもの

  • Reaction。プッシュを MVP から外したため。後から足す場合は独立テーブルの追加になるので、既存データの移行は不要。
  • ユーザー、セッション、セッションストア。Cookie を使わない。

7管理 API / MCP

MCP サーバーは本人専用。/mcp を Cloudflare Access で保護し、Worker 側で Cf-Access-Jwt-Assertion を検証する。MCP は AI 本文生成を行わず、クライアントが作った Markdown を保存する責務に絞る。

ツール引数戻り
create_achievement title, summary, slug?, occurred_at?, cover_image_url?, tags[], links[], body_markdown? id, slug, url, revision
list_achievements tags[], limit?, cursor?, include_deleted? items[], next_cursor
get_achievement id または slug 実績一式 + revision
update_achievement id, expected_revision, 変更するフィールドのみ id, slug, revision
delete_achievement id, expected_revision id, deleted_at
restore_achievement id id, revision
原本からの変更点

get_reaction_stats は削除（プッシュが無いため）。emblem と tier は追加しない。update_achievement の引数名は実装時に詰める要確認。

共通の決まり

  • 作成・更新・削除・復元は監査のため source を残す。
  • MCP で作成した実績は D1 に保存した時点で即時公開し、下書き状態を持たない。
  • 更新は expected_revision が一致しなければ失敗させる（同時更新で上書きしない）。
  • 削除はソフトデリート。復元可能。
  • 秘密情報をログに出さない。
  • 入力は valibot で検証する。

8共通 OGP 画像

X などのクローラーには全実績共通の固定画像を返し、実績ごとの差は D1 由来の共有メタデータで伝える。

仕様

項目決定
配置static/og/done.png を Workers Static Assets で配信
サイズ / 形式1200×630、PNG
内容サイト名と「やったこと」の共通デザイン。実績の title / summary / tags は画像に含めない
メタデータtitle と summary は SSR 時に D1 から取得して og:title / og:description に設定
配信要求ごとの描画・D1 読み出しなし。アプリ Worker が Static Assets を返す
個別画像生成・保存・revision 別 URL を作らない

9非機能

セキュリティ

  • /mcp は Cloudflare Access で保護。Worker 側でも JWT を検証する（多層防御）。
  • Markdown は読み取り時にサニタイズ。許可要素は見出し・段落・リスト・コード・リンク・画像・強調・引用のみ。raw HTML は無効。
  • 外部リンクは http / https のみ。別タブで開き rel="noopener noreferrer"。
  • 文字数に上限を設ける（title 120 / summary 200 / body 20,000 など）。
  • CSRF は Cookie を使わないため対象外。MCP はトークン認証のみ。

プライバシー

  • Cookie を発行しない。匿名IDもIPハッシュも持たない（プッシュを外したため）。
  • アクセス解析を入れない。Cloudflare の標準ログのみ。
  • プライバシーポリシーは「Cookie を使わない」「アクセス解析をしない」「Cloudflare のログが残る」の3点を短く書く。

パフォーマンス

  • 一覧は SSR で返し、20件 + 「もっと見る」。無限スクロールは使わない（SEO とアクセシビリティのため）。
  • OGP 画像は固定 PNG を Static Assets から返し、リクエスト時の描画や画像用 D1 読み出しを行わない。
  • 合計件数などの集計は都度 SQL で数える。集計テーブルは持たない。

可用性・復旧

  • D1 の Time Travel でポイント復元。加えて月1回のエクスポートを保管。
  • 削除・誤更新は achievement_revision から復元できる。
  • 書き込みは D1 のバッチで原子的に行う。

アクセシビリティ

  • 一覧・タグ・並び替えに適切なラベルを付ける。
  • 色だけで状態を表現しない。
  • 「もっと見る」はキーボードで操作できるボタンにする。

対応端末

スマートフォンと PC のレスポンシブ。モダンブラウザのみ。

10実装フェーズ

各フェーズは単独でマージできる粒度にし、終わったら PR を出す。

P0. 土台

  • SvelteKit 3 + Vite+ + TypeScript 6 + Tailwind v4 + shadcn-svelte の初期化。
  • lint / fmt / typecheck のスクリプトと GitHub Actions。
  • varlock の設定、cloudflare.config.ts、Cloudflare への接続。

完了条件: vp check と vp build が通り、空のページが Workers にデプロイできる。

P1. データ層

  • Drizzle のスキーマとマイグレーション。
  • リポジトリ層（作成・取得・一覧・更新・削除・復元）。
  • リビジョンの記録と復元。
  • Vitest でリポジトリ層のテスト。

完了条件: ローカル D1 に対して CRUD・楽観ロック・復元のテストが通る。

P2. 公開ページ

  • /done 一覧（タグ絞り込み、実施日降順、もっと見る）。
  • /done/<slug> 詳細（Markdown レンダリング、サニタイズ）。
  • SEO メタデータ、410 ページ、404 ページ。

完了条件: 手で投入したダミーデータで一覧と詳細が表示でき、Lighthouse の SEO が通る。

P3. 管理経路

  • 管理ロジックを MCP から呼べる形に分離。
  • /mcp に Streamable HTTP のエンドポイントを実装。
  • Cloudflare Access の検証。
  • MCP クライアントから実際に1件作成できることを確認。

完了条件: ローカルの MCP クライアントから作成・編集・削除・復元ができる。

P4. OGP と X 共有

  • 共通の 1200×630 PNG を Static Assets に配置。
  • D1 の title / summary を各詳細ページの共有メタデータに反映。
  • 詳細ページに X の投稿文面案と投稿画面へのリンクを表示。

完了条件: 実績ごとの title / description と共通画像が返り、投稿案から X の作成画面を開ける。

P5. 仕上げ

  • プライバシーポリシー、ホームページからの導線。
  • エラー時の表示、監視の確認。
  • バックアップ手順の文書化。

13受け入れ条件

  • MCP からタイトルと一言だけで実績を作成でき、即時公開される。
  • 任意でリンク・代表画像・複数タグ・詳細 Markdown を付けられる。
  • 一覧を実施日順で眺められ、タグで絞り込める。
  • 詳細 Markdown を後から追加・編集でき、見出し・リスト・コード・リンク・画像が表示される。
  • 編集すると revision が上がり、古い版に復元できる。
  • 削除すると 410 になり、復元できる。
  • 実績の URL を共有すると D1 の title / summary と共通 OGP 画像が出る。
  • 詳細ページから title / summary / URL を含む X 投稿文面案を開ける。
  • MCP から CRUD と一覧取得ができる。
  • スマホと PC で主要操作が破綻しない。
  • CI で typecheck / lint / test が通る。

14レビュー観点

  • 要確認 が付いた箇所の判断は妥当か。
  • P0〜P5 の順番と粒度は、1人で回せる大きさか。
  • 「MVP でやらないこと」に、実は必要なものが混ざっていないか。
  • データモデルに、後から足すと痛い制約が残っていないか（特に slug の不変化）。
  • 共通 OGP PNG のデザインと、実績ごとの SSR メタデータが共有時に意図どおり表示されるか。
